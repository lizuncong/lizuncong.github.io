**为什么启动**
- `Next.js 服务` / `Turbopack PostCSS`：dev 模式必要。
- `Codex CLI 主进程`：压测并发 10，每个任务一个 `codex exec`，必要。
- `Codex stdio MCP`：每个压测请求都注册并启动 `project_tools`，所以是 10 个；只在测工具调用时必要。
- `OpenAI plugins Git 链` / `Langfuse marketplace Git 链`：插件和 marketplace 版本检查，纯压测不需要。
- `Langfuse tracing` / `SkyComputerUseClient`：观测和 turn-ended 通知 hook，压测不需要。
- `Zsh 快照` / `dirname`：Codex 启动时捕获 shell 环境，纯作文任务不需要。
- `ps`：监控采样产生的短命进程。

**能否覆盖**
- 若只保留核心，112 个里约可减 **88 个观察进程**，剩 Next.js 2 个、Codex 10 个、MCP 10 个、监控 `ps` 2 个，共约 **24 个**。
- 如果再把抽屉里的 **Codex stdio 自定义工具调用**关掉，还可以少 **10 个 MCP 进程**，进一步降到约 **14 个**。
