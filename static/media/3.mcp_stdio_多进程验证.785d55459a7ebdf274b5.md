**为什么启动**

- `Next.js 服务`：`next dev` 启动，处理 monitor 页面、监控接口、压测接口。必要。
- `Turbopack PostCSS`：Next.js dev 模式的样式编译 worker。开发模式必要。
- `Codex CLI 主进程`：压测并发是 10，SDK 每个任务单独 `spawn` 一个 `codex exec --experimental-json ...`。必要。
- `project_tools MCP`：这次开启了“stdio MCP 多进程验证”，每个请求注册 3 个 `project_tools`，所以是 `10 × 3 = 30` 个。这是本次验证目标，不是额外噪音。
- `OpenAI plugins Git 链`：每个 Codex CLI 启动时检查内置 plugin marketplace 的远端 HEAD。8 次形成完整 `git ls-remote → git remote-https → git-remote-https` 三进程链，另 2 次只采样到短命 `git` 进程，共 26 个。纯作文任务不必要。
- `Langfuse marketplace Git 链`：全局配置启用了 Langfuse marketplace，每个任务 3 个进程，共 30 个。不需要 Langfuse 可以去掉。
- `Zsh 快照`：Codex 启动时捕获 shell 环境。相关 `bash/nvm`、`printf`、`head/tail/awk` 都是 shell 初始化副作用。纯作文任务不需要。
- `Langfuse tracing`：每个任务结束时的 Stop hook 启动 Node 进程上传 trace。只在需要观测时必要。
- `SkyComputerUseClient`：全局 notify 配置的 turn-ended 通知 hook。压测不需要。
- `ps`：monitor 自己采样进程指标时产生的短命进程。
- `已退出未回收`：一个 0 KB 的退出未回收 shell 进程，不占 CPU/RSS。

**能否覆盖**

- 纯压测下，OpenAI plugin sync、Langfuse marketplace 检查、Langfuse tracing、turn-ended 通知、shell snapshot 都可以省掉。
- 如果保留本次要验证的 `project_tools MCP`，可从 170 个降到约 **43 个核心/目标进程**：Next.js 2、Codex 10、project_tools MCP 30、监控 `ps` 1。
- 如果连 `project_tools MCP` 也关闭做基线，核心只剩约 **13 个**：Next.js 2、Codex 10、监控 `ps` 1。
- 最干净的做法是给压测路径单独 SDK 配置：禁用插件、hooks、shell snapshot，并避免全局 notify。
